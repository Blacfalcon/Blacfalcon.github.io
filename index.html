    About

    I’m a pilot who builds software for aviation teams: tools that plan, check and record flying operations, and that keep working offline.

    Flight Ops

    Source code

    A flight operations system for a military helicopter unit. It takes each sortie from aircraft serviceability to debrief, and it won’t let a sortie skip a step.

    1. Confirm aircraftEngineering
    2. Schedule + orderOps or Training Officer
    3. Approve orderCommand
    4. PublishOps Officer
    5. ReadinessT-60, every crew member
    6. Risk + IMSAFET-30, pilot in command
    7. ClearCommand
    8. FlyCrew
    9. Close outPilot in command

    Magenta steps run on a clock in the last hour before take-off. A background worker sends the readiness call, flags crew who don’t reply and reminds the pilot in command.

    Approvals in the right order

    Nine roles, each with its own permissions. A sortie can’t be published until command approves its mission order, and it isn’t cleared until command approves the risk assessment.

    Risk scored, not guessed

    Eight categories rated 1 to 5, plus an IMSAFE check from every crew member. The weather score is pre-filled from the latest METAR against ICAO minima.

    Weather in plain English

    METAR and TAF go in by a simple form that writes the code, or by pasting it. Everyone reads them in plain English.

    Works with no signal

    Readiness, risk, flight plans and debriefs are saved on the phone. They’re sent automatically when the connection comes back.

    Phone first, email for action

    Every item goes to the phone through Web Push or Firebase. Only items that need someone to act also go by email, and emails never carry operational detail.

    Reports that build themselves

    Daily, weekly, monthly and quarterly summaries, with hours in HH:MM and fuel in kg and litres. They export to PDF and Excel.

    Secure by default

    Admin activates every account. Command and admin roles use a two-step code, idle sessions sign out, and an append-only audit log records every change.

    One copy per unit

    Each unit sets its own name, home aerodrome, logo and watermark in Settings. The home aerodrome is picked from Nigerian ICAO locations.

    How it’s built

    Web
    Next.js 15, React 19, TypeScript, Tailwind CSS
    Data
    PostgreSQL with Prisma, S3-compatible file storage
    Jobs
    pg-boss worker for the mission clock, email, push and summaries
    Security
    argon2 passwords, rotating sessions, TOTP two-step sign-in, role-based access
    Mobile
    Installable web app with Web Push; Capacitor shell with Firebase for Google Play and the App Store
    Deploy
    Docker Compose behind Caddy with automatic HTTPS
